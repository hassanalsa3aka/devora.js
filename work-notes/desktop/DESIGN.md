# Design: an experimental desktop target (`devora desktop dev|build`)

Status: design. Opt-in; nothing changes for a website. Mobile, and Metro-class bundling and device tooling, come
later and are not part of this design or of the code.

## Goal

One codebase, one more output: the same routes that run as a website also run in a desktop window. The app's
server (pages, API routes, sessions) runs unchanged on the user's machine; the window only displays it.

## Shape

- **Shell: Tauri 2** (default and only shell in the first version). Rust core + the operating system's web view
  (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux).
- **Sidecar:** the shell starts the app's production server (`devora start`, adapter-node, bundled with a Node
  runtime as a Tauri sidecar binary) as a child process and shows its pages.
- **Build:** `devora desktop build` runs `devora build`, writes `src-tauri/` config from a template (no code from
  the app goes into Rust), and calls `tauri build`. `devora desktop dev` runs the same with `devora dev`.

## Security rules (each one a test where the container allows it; the rest a manual check)

| Rule | How |
|---|---|
| Loopback only | The sidecar binds `127.0.0.1` only (never `0.0.0.0`, never `::`), refused otherwise |
| Random port per launch | The shell asks the OS for a free port (bind to port 0, read it, pass it as `PORT`); never a fixed port |
| Per-launch token on every request | 32 random bytes, base64url, generated by the shell, passed to the sidecar in an environment variable (not a command-line argument, which other local users can read). The sidecar answers 403 to any request without `X-Devora-Desktop-Token: <token>` (constant-time compare). The web view adds the header to every request through Tauri's custom protocol / request hook; a browser tab on the same machine pointed at the port gets 403 |
| One origin | The window loads only `http://127.0.0.1:<port>`; `allowedHosts` is set to `127.0.0.1` for the sidecar |
| Navigation lock | Tauri's navigation handler refuses any URL whose origin is not the sidecar's; links to other origins open in the system browser only after a check that the scheme is `https:` (never `file:`, `javascript:`, custom schemes) |
| No `window.open` | New-window requests are refused (or sent to the system browser by the same check) |
| Strict CSP | The app's CSP stays `default-src 'self'`; the Tauri `csp` setting is the same policy, plus `connect-src 'self'` |
| No remote code | No remote URL is ever loaded in the window; no `eval`; the bundle contains everything |
| IPC allowlist, default none | Tauri capabilities file grants **no** commands by default. An app that needs one lists it by name in `app.config.ts` (`desktop: { ipc: ["open_file_dialog"] }`); anything else is denied |
| Secrets | Session secret and any credentials go in the OS keychain (Tauri plugin `stronghold` or `keyring`), never in files next to the binary; the sidecar gets them through the environment at launch |
| Updates | No auto-update unless the update is signed (Tauri updater with a public key in the config); off by default |
| Refuses production misuse | `devora desktop` refuses `--host`; the token check cannot be turned off |

## Tauri or Electron

| | Tauri 2 | Electron |
|---|---|---|
| Attack surface | OS web view, Rust core, capabilities deny by default; no Node in the renderer | Bundled Chromium + Node; `contextIsolation`, `sandbox` and `nodeIntegration: false` must all be set right; larger history of renderer-to-Node escapes when misconfigured |
| Size (empty app, typical) | a few MB plus the Node sidecar (~40–90 MB with a bundled Node) | ~80–150 MB (Chromium + Node) |
| Effort for Devora | Needs a Rust toolchain to build, a sidecar for Node, and the token header via Tauri's request hook | Node is already there (the server can run in the main process); more familiar to JS developers |
| Rendering consistency | Differs per OS web view (WebKit on macOS/Linux) | Same Chromium everywhere |

Decision: **Tauri**, for the smaller attack surface and deny-by-default capabilities. The cost is the Node sidecar
(size) and WebKit differences on macOS and Linux.

## What the code in this repository does (when implemented) and what it cannot do here

- `packages/desktop` (`@devorajs/desktop`, private): the sidecar side, which is plain Node and testable here:
  the token middleware, loopback-only binding, random port, the origin and navigation policy as data
  (`isAllowedNavigation(url, origin)`), the IPC allowlist parser, and the generated `tauri.conf.json` and
  capabilities file.
- The container has no display, no Rust toolchain for desktop targets and no signing keys: building the window,
  clicking through it, signing and notarizing are manual steps (see `MANUAL-CHECK.md` when written).
